# Spec 17 — Loop Hardening: Reconnect, Stuck Detection, Budgets, Project Instructions, Lean Errors

**Status:** Draft, revision 16 (fourteen design-critic, fourteen security-critic and seven friction-critic passes; the closing round's three signed resolutions of 2026-10-09 and its implementer notes folded in, see §13)
**Version target:** 0.18.0
**API version:** `PLUGIN_API_VERSION` unchanged ("1")

---

## 1. Problem

Over two days of real work on this repository (five sessions, 21 child-agent runs, ~20M input tokens), the loop lost or degraded turns for reasons that are the harness's to fix:

| What happened | Count | Cost |
|---|---|---|
| Model server restarted mid-generation (GPU Xid 8); the turn failed on the first "peer closed connection" or refused `/tokenize` | 2 turns, 1 child | a 24-minute turn and a critic run, both recovered only by the user typing "continue" |
| Stuck detector escalated on legitimate loops: 7 identical `git push` retries after a GitHub 500, 6 identical `gh run list` polls while a workflow ran | 2 turns | both killed; the "[Agent stuck …]" notice leaked into the reply, once with an empty summary |
| `max_actions=100` ended an "implement this spec" turn at 51 iterations | 1 turn | honest handoff, but a second turn to finish |
| A read-only workspace-defined critic (15 actions in its workspace file; the machine-level copy that ran carried 30) ran out while reading whole modules and reported a false CRITICAL ("tests/ missing": it globbed `tests/` not `tests/unit/`) | 1 child | a wrong finding the orchestrator had to refute |
| Tool-result defaults are absolute (32,000 chars) on a 65K window | every turn | one tool result can occupy an eighth of the window |
| No project-level instructions; the release flow was rediscovered twice, `python` vs `python3` missed once | 3 turns | ~15 iterations |
| `CompactionTriggered` published with an empty session id; `history.jsonl` rows carry `model: ""`, `latency_ms: 0` | 13 events, every row | session analysis has to be reconstructed from the bus |
| Error texts are paragraphs ("dispatch not wired", the ingest-via-exec refusal) or omit the one useful hint (`bash_exec` timeout) | — | tokens and retries |

**Out of scope here, by decision:** the `task` tool and working record. It gets its own spec (18): the evidence (60 calls, 16 rejected; a 9,470-token reference pinned on up to 424 requests; one record spanning three jobs) is recorded in the 2026-10-07 session review and belongs to that design, not to a patch list.

**Found by the review, pre-existing, fixed here because the same code is touched:** the shell classifier treats `git diff|log|show --output=<file>` and `git diff --no-index <any path>` as read-only (`_git_targets` names no target for these verbs); `git_config_dangerous_keys` lacks `diff.*.textconv`, `pager.*`, `credential.*.helper` and `filter.*.process`; and a workspace `agents/explore.yaml` can lift a built-in child's `max_actions` to the schema ceiling because `_narrow_builtin_overlay` never clamps budgets. The first two are in §7.3, the third in §7.2.

## 3. Goals

- G1. A model-server restart costs at most one bounded wait, never the turn.
- G2. A repeated call with a changing **trusted** result is progress, not stuckness. Stuck notices go to the bus and status line, not the reply.
- G3. No magic-number budgets: the interactive root agent is uncapped and bounded by the human, the gate and the tool surface; children by a share of the parent when the parent is finite, by their own configured ceiling where one is configured, and by the root's rung under an attended local root; unattended surfaces by a named config value. A cloned repository can only lower budgets, never lift them.
- G4. Context defaults are ratios of the window, resolved where the window is known.
- G5. Project instructions are used, named, never generated, never injected silently, recorded per root, and fenced as project text.
- G6. Events and history rows carry their session, model and latency.
- G7. Error texts state the fact and the one sanctioned alternative; resolved failures leave the model's view at request build, never the record.

## 4. Non-goals

- Changing the stuck ladder's thresholds or nudge text (one added sentence).
- Any change to the permission gate's decisions or the capability floor beyond §7.3's classifier corrections (the write-shaped and inline-dangerous flags, the env-assignment prefix); the ingest-via-exec refusal keeps blocking, it just says less.
- The task record (spec 18).
- A project map / just-in-time indexing (§8.4 is the direction only).
- Wiring `system_prompt_file`/`microagents`; §8.2 uses a loop constructor argument beside `guardrails_path` and leaves those two as they are.

## 6. Stuck detection on call plus trusted result (G2)

- `record(name, arguments)` becomes `record(name, arguments, result)` where `result` is an **exact** hash of `(success, result_content)`. No normalization layer: a varying error body is, by definition, changing state. The call sites already run after the observation exists, so the ladder's semantics (`classify()` once per iteration, clean slate after a warning) do not move.
- The hash is included **only for tools whose schema declares `result_origin: trusted`** (read off the registry the way `context.py` reads it for eviction; the registry lookup fails closed). Web, MCP and memory results are untrusted and keep call-only signatures, so a page or server that varies a nonce per reply cannot buy an endless loop. `bash_exec` and `agent` are declared trusted, so their output is hashed even though its bytes can be attacker-influenced; see §10 for why that is liveness only.
- **A second, call-only counter is added** (today there is none): a **per-turn monotonic tally per `compute_signature(name, args)`**, not a window — independent of `window_size` and never touched by the nudge's `_window.clear()` — with its threshold `stuck_detector.call_only_multiplier × escalation_threshold` (`call_only_multiplier` is `ge=1` with an upper bound and a documented default of 3). It escalates regardless of the result. The hashed signature drives the recovery nudge and the existing ladder; the call-only counter is the ceiling. Both are named in spec 03's `StuckDetector` block.
- **`stuck_detector.*` becomes machine-only, with an enforcer.** `AGENT_GLOBAL_ONLY_FIELDS` is a label whose two members each have bespoke code and whose one generic consumer sees plugin sections alone, so listing a core key there would enforce nothing. Instead a core-**section** narrowing step, driven by a new `AGENT_CORE_GLOBAL_ONLY_SECTIONS = frozenset({"stuck_detector"})`, runs at **both** workspace doors and **restores the whole section, never key by key**: a loop copied from `_narrow_agent_global_only` skips keys the workspace file omits, and `merged` starts as the workspace file's own dict, so an omitted `escalation_threshold` would lift a stricter global value to the schema default with no warning — the very hole §2 names. In `load_agent_file`, after step 5c and gated on `in_layer(path, self._local_dir)` like step 6, `merged["stuck_detector"]` becomes the global `agents/<stem>.yaml`'s section, else the global overrides' `agent:` section's, else absent (the schema default), with one "only the global config may set it" note through `self.agent_warnings` when the sections differ. Inside `_narrow_builtin_overlay` the same replacement uses the global `agents/<name>.yaml`'s section, else `base.stuck_detector`, and reports through `log.warning`, because `agent_warnings` is read once at start while that door runs at dispatch time — routed to the channel's status line through the bus (§8.2), never `logging.lastResort`; every such note spells the path `{str(path)!r}` as `loader.py:762` does, so a crafted stem carries no control character into the line. No org or division rung exists, so those are the only doors. A workspace file can then no longer lift `escalation_threshold`, shrink `window_size`, or raise the multiplier, because this counter is what bounds the uncapped root (§7.1). The pre-existing silence (`escalation_threshold` above `window_size`) is closed by the same change for workspace files; the machine layer keeps full authority. The two logged cases split as intended: seven `git push` retries carried the same remote error text and would still escalate through the ladder; six `gh run list` polls carried changing durations and would run until the call-only ceiling.
- The reply no longer gets "[Agent stuck …]" appended, and the person hears about one escalation **once**: today it arrives three times — the reply suffix, `on_escalation`'s `send_error` (`channels/base.py:463`) and `on_turn_failed`'s (`:410`). The reply suffix goes; `on_escalation` is the one delivery (the terminal already subscribes); `TurnFailed.detail` for a stuck-ended turn carries the reply summary and no stuck text, so `on_turn_failed` adds no second line; the stuck summary stays on the bus.
- The recovery nudge gains one sentence: "If you are waiting on something external, say so and stop; do not poll." It is the only prompt-side change.

A hard link to an outside file resolves inside, opens under `O_NOFOLLOW` and is bound by the hash — the yes covers bytes, not an inode — and a root that is itself a symlink re-pointed later resolves to a new store key and is treated as a new root (the fresh-offer clause or the dim line, never a prompt of its own).

## 10. Security

- `git_read` runs no repository-configured command: textconv drivers, external diff, pager, hooks, fsmonitor, signature programs, a promisor remote's lazy fetch and `-c` are out of reach by construction, the environment carries no inherited `GIT_*`, and the one path git offers no flag for — clean and process filters on a worktree-reading `diff` — is closed by the config precheck, which narrows the diff to unbound paths through attribute magic and fails closed on any other outcome. The `-c core.hooksPath=/dev/null -c core.fsmonitor=false` prefix, not the verb, is what keeps a read from running two hooks: a bare `git diff` refreshes the index and fired both `post-index-change` and a configured `core.fsmonitor` program (verified on 2.53.0); under the prefix neither ran, and an injected `GIT_CONFIG_PARAMETERS` cannot override it because the environment is from scratch and `-c` wins regardless. It never leaves the resolved workspace root: toplevel, git dir and common dir are pinned, alternates are refused, submodules are never opened, and `paths[]` can name nothing outside it — an absolute path outside the root (one inside is relativized), `..` after `normpath`, leading `-`, empty, control characters and `:(prefix:` are rejected before argv, magic is never parsed by git's lexical no-index test, and `--` is always emitted — so git's implicit `--no-index` with two paths is unreachable, and the one-argument form it can still reach (a `revision` that is an outside path, no `paths[]`) dies on git's usage error before anything is read. The tool is absent when the derived boundary is `None` or the registration-time pins fail.
- Project instructions are attacker-controlled text from a workspace file. They enter the role fenced as project text under a harness header, after the one trust prompt on a fresh clone or with a visible line on a root whose layer already loads — a line a channel delivers to a person, after which the handle's `on_delivered` writes the record; a changed file is adopted with a visible line when no call of the harness named it, and dropped, marked and offered back through `/instructions on` when one did. The door this is smaller than: a project `agents/<agent>.yaml` already replaces the root's entire `role` unfenced, before Guardrails, with no prompt beyond the layer's own yes (`loader.py:733–747`). The store is in `PROTECTED_CONFIG_DIR_ENTRIES` (`gate_types.py:832–839`) beside `trusted_workspaces.yaml`, which it resembles — a per-root yes; `coauthor_consent.yaml` is not, and a `write` of an unlisted config-dir file is ALLOW in `auto` through `verdict.evaluate`, so an unprotected store would let the root, or a config child holding `write`, clear every mark and set `yes` under its own hash. The store takes an advisory `flock` on a dedicated sidecar, `project_records.yaml.lock`, held across read → modify → write — never on the data file itself, because `atomic_write_overlay` replaces the inode (`overlay.py:121–148`) and a lock on the retired inode excludes nobody: two sessions would race, and a lost `harness_written` mark fails toward adopting the model's file; the sidecar sits beside the store in `PROTECTED_CONFIG_DIR_ENTRIES`, since a replaced lock file is lost exclusion too; a stale lock from a crash is no problem, advisory locks release on close. The residual, in the same class as the blind yes the owner accepted on 2026-10-07: a root in `auto` that writes an instructions file without naming it in any call's arguments, through an MCP filesystem tool, through a hard link written later, through a repository hook run by a reader-listed `git add`/`git commit` (a clone carries no active hooks; installing one asks), or through a detached process landing between turns, gets its text into its own role under the `changed, using it` line — text it could already put in front of itself through any file read, fenced here, bounded by the gate and the capability floor, and visible to the person at the next turn (§13).
- A cloned repository cannot lift a budget, null a cap, widen a share or ratio, raise `channels.unattended_max_actions`, weaken `stuck_detector.*`, or set `instructions.children` either way (§6, §7.1, §7.2, §8.2) — through either workspace door, the shadowing agent file or the built-in overlay; and no configured value, from any layer, exceeds `channels.unattended_max_actions` on a remote unattended surface, because the loop applies the knob as a ceiling (§7.1). The workspace-lowerable set is exactly `max_actions` and `max_duration_minutes` (`AGENT_CORE_LOWER_ONLY_KEYS`, §7.1), `review_share`, `lookup_share`, `tool_output_ratio`, `evict_ratio`, `result_cap_ratio` and `children_budget.*.{actions, minutes}` — lower is safer for each (less untrusted text per result and into history, smaller children) and none sizes a safety margin; `reconnect_wait_seconds` moves both ways under its `le`, liveness only; `instructions.max_ratio`, `call_only_multiplier` and `unattended_max_actions` are machine-only.
- Reconnect re-sends an identical request; it never re-runs a tool call.
- Untrusted-origin output cannot delay escalation (§6). Trusted-origin tools whose content is attacker-influenced (`bash_exec` reading a cloned file, `agent` relaying a web summary) can delay it, bounded by the call-only ceiling and the human; the effect is liveness only, never a privilege change, and identical results still escalate as today.
- `git_read` fails closed on a repository with dubious ownership (no `safe.directory` is injected, by design), on a gitdir-file or `commondir` pointing outside the root, on `objects/info/alternates`, on a parent repository above the workspace (`GIT_CEILING_DIRECTORIES`), and, in a repository that configures a clean or process filter, a worktree-reading `diff` reads only the paths the filter does not bind.
- The compaction-view drop never hides a denial or a `host: dangerous` failure (§9).
- History rows gain only integers from `CompletionUsage` and a model name; the file stays 0600.
