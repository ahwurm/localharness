## 1. Problem

Over two days of real work on this repository (five sessions, 21 child-agent runs, ~20M input tokens), the loop lost or degraded turns for reasons that are the harness's to fix:

| What happened | Count | Cost |
|---|---|---|
| Model server restarted mid-generation (GPU Xid 8); the turn failed on the first "peer closed connection" or refused `/tokenize` | 2 turns, 1 child | a 24-minute turn and a critic run, both recovered only by the user typing "continue" |
| Stuck detector escalated on legitimate loops: 7 identical `git push` retries after a GitHub 500, 6 identical `gh run list` polls while a workflow ran | 2 turns | both killed; the "[Agent stuck …]" notice leaked into the reply, once with an empty summary |
| `max_actions=100` ended an "implement this spec" turn at 51 iterations | 1 turn | honest handoff, but a second turn to finish |
| A read-only critic (15 actions in the repo file; the machine-level copy that ran carried 30) ran out while reading whole modules and reported a false CRITICAL ("tests/ missing": it globbed `tests/` not `tests/unit/`) | 1 child | a wrong finding the orchestrator had to refute |
| Tool-result defaults are absolute (32,000 chars) on a 65K window | every turn | one tool result can occupy an eighth of the window |
| No project-level instructions; the release flow was rediscovered twice, `python` vs `python3` missed once | 3 turns | ~15 iterations |
| `CompactionTriggered` published with an empty session id; `history.jsonl` rows carry `model: ""`, `latency_ms: 0` | 13 events, every row | session analysis has to be reconstructed from the bus |
| Error texts are paragraphs ("dispatch not wired", the ingest-via-exec refusal) or omit the one useful hint (`bash_exec` timeout) | — | tokens and retries |

**Out of scope here, by decision:** the `task` tool and working record. It gets its own spec (18): the evidence (60 calls, 16 rejected; a 9,470-token reference pinned on up to 424 requests; one record spanning three jobs) is recorded in the 2026-10-07 session review and belongs to that design, not to a patch list.

**Found by the review, pre-existing, fixed here because the same code is touched:** the shell classifier treats `git diff|log|show --output=<file>` and `git diff --no-index <any path>` as read-only (`_git_targets` names no target for these verbs); `git_config_dangerous_keys` lacks `diff.*.textconv`, `pager.*`, `credential.*.helper` and `filter.*.process`; and a workspace `agents/explore.yaml` can lift a built-in child's `max_actions` to the schema ceiling because `_narrow_builtin_overlay` never clamps budgets. The first two are in §7.3, the third in §7.2.

## 3. Goals

- G1. A model-server restart costs at most one bounded wait, never the turn.
- G2. A repeated call with a changing **trusted** result is progress, not stuckness. Stuck notices go to the bus and status line, not the reply.
- G3. No magic-number budgets: the interactive root agent is uncapped and bounded by the human, the gate and the tool surface; children by a share of the parent when the parent is finite, else by their own configured ceiling; unattended surfaces by a named config value. A cloned repository can only lower budgets, never lift them.
- G4. Context defaults are ratios of the window, resolved where the window is known.
- G5. Project instructions are offered, shown, never generated, never injected without a recorded yes, and fenced as project text.
- G6. Events and history rows carry their session, model and latency.
- G7. Error texts state the fact and the one sanctioned alternative; resolved failures leave the model's view at request build, never the record.

## 4. Non-goals

- Changing the stuck ladder's thresholds or nudge text (one added sentence).
- Any change to the permission gate's decisions or the capability floor; the ingest-via-exec refusal keeps blocking, it just says less.
- The task record (spec 18).
- A project map / just-in-time indexing (§8.4 is the direction only).
- Wiring `system_prompt_file`/`microagents`; §8.2 uses a loop constructor argument beside `guardrails_path` and leaves those two as they are.

## 5. Reconnect and retry (G1)

Re-based on the existing one-shot reconnect (`loop.py:1622–1637`), which it replaces rather than duplicates:

1. `_wrap_error` maps `httpx.TransportError` and `httpx.RemoteProtocolError` to `ProviderConnectionError`, so a mid-stream drop reaches the same handler as a refused connect.
2. A per-turn `reconnect_used` flag joins the one-shot flags at `loop.py:90–99`. `ProviderConnectionError` is caught at **both** seams where nothing has been appended yet: `_build_request` (the `/tokenize` counter) and `stream_complete`. At the `_build_request` seam the catch runs `_absorb_commit` before retrying, because `build_messages` may have committed just before the failing count. The loop publishes `ProviderLost(agent_id, session_id, detail)` **once, before the wait**, and the terminal renders the status line from it: "model server unreachable — waiting up to Ns; Esc stops". The bus is async (`EventBus.publish`, `core/bus.py:87`) and `on_poll` is a sync callback, so the elapsed time is not pushed through `on_poll`; the terminal keeps the line from `ProviderLost`'s bound the way it tracks `Heartbeat` (`loop.py:1559` → `channels/terminal.py:2160`), and Esc is the wait raced against the interrupt.
3. The loop calls the **existing** `provider.server.wait_ready(base_url, config_dir=None, timeout_seconds=bound, poll_seconds=_QUEUE_VISIBILITY_SECONDS, **key_kwargs(api_key))` — it already polls `{base_url}/models` until 200, where a 503 (llama.cpp still loading) is not ready by construction — rather than growing a second probe on the client. `config_dir=None` makes it a pure poll (no pidfile check, no log tail: the server may be hand-run). `base_url` and `api_key` are read **at reconnect time from `self._llm.config`** — the client's own address and `provider.api_key`, the key the re-sent request carries to the same `base_url`, so no new destination learns it — never `_launch_key`/`required_key_kwargs`, which answer `{}` for a hand-run keyed server and would poll keyless into a 401 for the whole bound; `rebind_endpoint` mutates that config mid-session, so it is not captured at construction. `key_kwargs` (`server.py:48`) sends no header for a missing or `"none"` key. Nothing can print the key: `wait_ready` logs nothing, `on_poll` receives a float, and the `TimeoutError` text carries seconds and, with no `config_dir`, no log tail. TCP accept is not readiness.
4. On ready: `continue`, exactly the overflow retry's shape (`loop.py:1647–1658`) — rebuild and re-send; nothing was appended to `session.messages` (`loop.py:1745` is the first push) and tool calls are extracted after the full message (`:1753`), so a re-send can never re-run a tool. Child loops do the same.
5. The bound is a **named knob, `provider.reconnect_wait_seconds`** (`0` = reconnect off, default documented beside it, bounded with `le=` as `max_duration_minutes` is), not `inference_queue_wait_seconds`, whose `0`/`null` means the opposite ("wait indefinitely") and must keep meaning that. With reconnect off, the single fallback retry remains, and its delay is `_QUEUE_VISIBILITY_SECONDS` — the literal `2.0` goes away. On Discord and mobile the bound applies with no Esc.
6. Only after the bound passes (`wait_ready` raises `TimeoutError`, caught at the same seam), or the retry fails: today's `TurnFailed(llm_error)` with today's text.

## 6. Stuck detection on call plus trusted result (G2)

- `record(name, arguments)` becomes `record(name, arguments, result)` where `result` is an **exact** hash of `(success, result_content)`. No normalization layer: a varying error body is, by definition, changing state. The call sites already run after the observation exists, so the ladder's semantics (`classify()` once per iteration, clean slate after a warning) do not move.
- The hash is included **only for tools whose schema declares `result_origin: trusted`** (read off the registry the way `context.py` reads it for eviction; the registry lookup fails closed). Web, MCP and memory results are untrusted and keep call-only signatures, so a page or server that varies a nonce per reply cannot buy an endless loop. `bash_exec` and `agent` are declared trusted, so their output is hashed even though its bytes can be attacker-influenced; see §10 for why that is liveness only.
- **A second, call-only counter is added** (today there is none): a **per-turn monotonic tally per `compute_signature(name, args)`**, not a window — independent of `window_size` and never touched by the nudge's `_window.clear()` — with its threshold `stuck_detector.call_only_multiplier × escalation_threshold` (`call_only_multiplier` is `ge=1` with an upper bound and a documented default of 3). It escalates regardless of the result. The hashed signature drives the recovery nudge and the existing ladder; the call-only counter is the ceiling. Both are named in spec 03's `StuckDetector` block.
- **`stuck_detector.*` becomes machine-only, with an enforcer.** `AGENT_GLOBAL_ONLY_FIELDS` is a label whose two members each have bespoke code and whose one generic consumer sees plugin sections alone, so listing a core key there would enforce nothing. Instead a core-**section** narrowing step, driven by a new `AGENT_CORE_GLOBAL_ONLY_SECTIONS = frozenset({"stuck_detector"})`, runs at **both** workspace doors and **restores the whole section, never key by key**: a loop copied from `_narrow_agent_global_only` skips keys the workspace file omits, and `merged` starts as the workspace file's own dict, so an omitted `escalation_threshold` would lift a stricter global value to the schema default with no warning — the very hole §2 names. In `_load_agent_yaml`, after step 5c and gated on `in_layer(path, self._local_dir)` like step 6, `merged["stuck_detector"]` becomes the global `agents/<stem>.yaml`'s section, else the global overrides' `agent:` section's, else absent (the schema default), with one "only the global config may set it" note through `self.agent_warnings` when the sections differ. Inside `_narrow_builtin_overlay` the same replacement uses the global `agents/<name>.yaml`'s section, else `base.stuck_detector`, and reports through `log.warning`, because `agent_warnings` is read once at start while that door runs at dispatch time. No org or division rung exists, so those are the only doors. A workspace file can then no longer lift `escalation_threshold`, shrink `window_size`, or raise the multiplier, because this counter is what bounds the uncapped root (§7.1). The pre-existing silence (`escalation_threshold` above `window_size`) is closed by the same change for workspace files; the machine layer keeps full authority. The two logged cases split as intended: seven `git push` retries carried the same remote error text and would still escalate through the ladder; six `gh run list` polls carried changing durations and would run until the call-only ceiling.
- The reply no longer gets "[Agent stuck …]" appended. `TurnFailed.detail` is composed separately from the reply summary, the terminal renders the notice from the `Escalation` it already subscribes to, and the stuck summary stays on the bus.
- The recovery nudge gains one sentence: "If you are waiting on something external, say so and stop; do not poll." It is the only prompt-side change.

### 7.3 A read-only git tool, read-only by construction

A new built-in `git_read` tool with **structured parameters**, like `grep_tool`, and no free-form argv:

- `subcommand ∈ {diff, show, log}`, `revision` (validated: non-empty, no leading `-`, no control characters; `..` and `...` stay legal because they are range operators), `paths[]` (**validated** before argv: no absolute path, no `..` component after `os.path.normpath`, no leading `-`; `:(top)`, `:(glob)`, `:(attr:)` and `:(literal)` magic stays legal — git's implicit `--no-index` test is lexical on the raw strings with magic unparsed, so a magic path never reaches it, and a magic path that walks up (`:(top)../x`, `:/../x`) either matches nothing from the top or, for `:(literal)`, hits git's own "outside repository" fatal (verified, §2); the `..` rule still applies to the raw string, which also rejects `':/../../x'` (`normpath` → `../x`), the one spelling that reached `--no-index` through a directory named `:`; `:(prefix:` is rejected because it trips git's `BUG()` (SIGABRT), and an empty entry and any NUL or control character are rejected as `revision` rejects them; passed after `--`, **always emitted**, so a `revision` such as `/etc/passwd` with no paths dies on git's usage error and never reaches the implicit branch), `max_lines`, `stat: bool`, `cached: bool` (`diff` only: the index against `revision`). `<rev>:<path>` reads objects only; a single pathspec outside the worktree is fatal in git itself, but **two** paths with at least one outside become git's implicit `--no-index` and diff the filesystem, directories included (verified, §2) — which is why `paths[]` is validated rather than entrusted to `--`; `:(top)`, `:(glob)`, `:(attr:)` are filters without execution; `-L`, `-S`, `--output` and the `--no-index` token are unreachable.
- argv built by the tool with a fixed prefix: `git --no-pager -c core.fsmonitor=false -c core.pager=cat -c core.hooksPath=/dev/null -c log.showSignature=false -c color.ui=never -c diff.submodule=short <verb> --no-ext-diff --no-textconv`; no `-c`, `--output`, `--no-index`, `--ext-diff`, `--exec-path`, `-C`, `--git-dir`, `--work-tree`, `--help` can ever appear because no caller-supplied token reaches argv unvalidated.
- Environment built from scratch: `PATH`, `HOME`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_NO_LAZY_FETCH=1` (a partial clone's promisor remote would otherwise make `show`/`diff` of a missing blob spawn `git fetch` — the user's own remote, but a repository-configured command all the same), `GIT_CEILING_DIRECTORIES=<realpath(root).parent>` (git realpaths each entry and compares against the physical cwd, so the ceiling is derived from the same resolved root the cwd is pinned to, never from a symlinked path, and never with a leading empty entry) so discovery never opens a parent repository, no inherited `GIT_*`. `cwd` pinned to the resolved workspace root — the gate's derived boundary (`derive_session_boundary`, `cli/start_cmd.py:1448–1450`), not `register_builtin_tools(workspace_root=…)`, which is `None` by default (`:1181–1183`) and would leave the three pins without a root in the common case; `rev-parse --path-format=absolute --show-toplevel --git-dir --git-common-dir` (one call; `--git-common-dir` otherwise prints `.git` or `../.git` relative to cwd) must put all three inside it (a `.git` gitdir-file pointing elsewhere is refused, and so is a `commondir` file that would redirect refs, objects and `config` to another repository, where `HEAD` would then resolve); the tool refuses when `objects/info/alternates` exists under the **common dir** (that is where git reads it; in a linked worktree `$GIT_DIR/objects` does not exist); and `-c diff.submodule=short` in the prefix keeps `diff` from opening a submodule's own git dir, which no ceiling governs. `stdin` DEVNULL, timeout, output cap; a non-zero or negative returncode (a signal, as git's `BUG()` abort) is a failure reported with git's stderr, never an empty success. No `-c safe.directory`: a repository with dubious ownership fails closed with git's own error, and that is accepted (§10).
- **Worktree-reading shapes and clean filters.** Verified on git 2.53.0 (§2): a `diff` with zero or one revision and no `cached` compares worktree files, and git canonicalizes each through its clean filter — `filter.<driver>.clean` or `.process` from `.git/config`, bound by `.gitattributes`, `.git/info/attributes` or `core.attributesFile` — before comparing; no flag disables it, and `--no-ext-diff --no-textconv` do not touch it. `cached`, two-revision `diff`, `show` and `log -p` compare blobs and run nothing. So before every `diff` without `cached` (no parsing of `revision` for `..`; one read per call) the tool runs `git config --get-regexp '^filter\..*\.(clean|process)$'` under the same environment (a read; it executes nothing): exit 0, a driver is configured → refuse with one line naming the key and the two shapes that still work (`cached: true`, two revisions), the dubious-ownership rule's shape; exit 1, no match → proceed; anything else → fail closed with git's stderr. Drivers reached through `[include]`, `[includeIf]` and `config.worktree` are seen by the precheck and the diff alike, so nothing the diff would honour escapes it; no cache keyed on config mtime, which would miss exactly those. A `filter=` attribute with no configured driver is a no-op in git and needs no check. The repository's own `.git/config` is the only config left after `GIT_CONFIG_NOSYSTEM=1 GIT_CONFIG_GLOBAL=/dev/null`, so a user's global LFS setup never trips it; a repository that ran `git lfs install --local` does, and is told so.
- Declaration: `gate_family="allow", host="safe", ingest="none", result_origin="trusted"`, like `grep_tool`; `ingest` is declared explicitly because the default is `"untrusted"` and the root floor would deny the tool. Registered in `register_builtin_tools` beside bash/write/edit, rooted at the derived boundary (above) rather than the opt-in `workspace_root`; added to `CONFIG_CHILD_DEFAULT_TOOLS` and to the two critic YAMLs' `tools.add`; `EXPLORE_TOOLS` unchanged; the declaration oracle test gains the row.
- **Pre-existing gaps closed alongside, with no added friction:** `_git_targets` marks only the two shapes `diff|log|show --output=<f>` / `--output <f>` and `diff --no-index` as write-shaped; a plain `git diff`, `git log` or `git show` through `bash_exec` is classified exactly as today and never starts asking. `GIT_CONFIG_DANGEROUS_KEYS_DEFAULT` gains `diff.*.textconv`, `pager.*`, `credential.*.helper` (the glob matcher already covers `credential.https://x.helper`) and `filter.*.process` beside `filter.*.clean`, which only changes the class of a `git config` write of those keys. The tool does not depend on either list.

### 8.2 Project instructions: a quick per-workspace hook (G5)

- **When:** a workspace-open hook in `start`, scoped to that workspace: it runs once when the harness sees a workspace whose `.localharness/` layer is loaded (the project you stand in, or an outside workspace with an answered Yes), on a channel that can ask. It does nothing in a declined or no-terminal session.
- **What:** the hook looks for `CLAUDE.md`, then `AGENTS.md`, then `.localharness/INSTRUCTIONS.md`; exactly one is resolved. Silently, with no prompt: a symlink leading outside the workspace or a non-regular file is skipped (as `layer_files(contained=True)` does: `leaves_layer` resolves both sides, so a link that stays inside is kept), the found name is shown in the ask, and the record's `path` is the **resolved real path** (`Path.resolve()`, checked inside the resolved root — the `coauthor._normalize_root` spelling): the per-assembly open below uses `O_NOFOLLOW`, which would fail on the link itself at every turn, while on the real file it opens what the yes covered and refuses a later swap of that file into a symlink; control and escape sequences are stripped for display, and a file over `instructions.max_ratio` of the window (tokens, converted through `APPROX_CHARS_PER_TOKEN`) is skipped with one log line. The harness never writes an instructions file.
- **The ask:** one line, nothing else: "Use `CLAUDE.md` (2.1 KB) as this project's instructions? (y/n)". The answer and the file's `sha256` — over the **raw bytes**, the bytes the user said yes to, never the stripped text — are recorded per resolved root (`Path(root).resolve()`, as `coauthor.py` keys) in `~/.localharness/project_instructions.yaml`, a 0600 store shaped like `config/coauthor.py`. A changed hash re-asks the same one line once. No preview, no diff display: the owner's ruling is quick and frictionless, and the file is the user's own repository in the common case.
- **Store:** a separate file, not `trusted_workspaces.yaml`, because that store is consulted only for workspaces outside the project you stand in (`trust.py` docstring). The two critics split on this; the ruling is recorded in §13.
- **Where it goes:** not through `role_sections`, which is the experiment overlay joined before Guardrails and mutable through `components set`. Instead a loop constructor argument `project_instructions: ProjectInstructions | None` beside `guardrails_path` — a frozen dataclass from `config/project_instructions.py` carrying `(path: Path, sha256: str)`, the store's own record; a bare string could be neither re-read nor re-hashed. The loop re-reads `path` at every assembly, as `_read_guardrails` re-reads its `Path` (`loop.py:1020–1035`) but **with the hook's own guards, never a bare `read_text`**: `os.open(O_RDONLY | O_NOFOLLOW | O_NONBLOCK | O_NOCTTY | O_CLOEXEC)` on the recorded real path, `fstat` must show a regular file (a symlink, FIFO or device is refused without blocking) of at most `instructions.max_ratio × window × APPROX_CHARS_PER_TOKEN` bytes, at most cap + 1 bytes are read, and those bytes are hashed and compared — a `git checkout` can turn the file into a symlink to `/dev/zero` and an in-project write into a FIFO, and a hash cannot guard a read that never returns. On any guard failure or hash mismatch the section is dropped for that turn with one log line under an `_instructions_warned` flag mirroring `_guardrails_warned`. The text is appended **directly after the Guardrails block** (`:1419–1421`) as a fenced section under a fixed harness header that says it is project text, not harness policy, once per request. The fence is unforgeable: a per-process random tag — a module-level `secrets.token_hex(16)` in `agent/loop.py`, per-process by construction — opens and closes it, and any line of the file equal to the closing marker is neutralized, so a `CLAUDE.md` cannot close the fence and impersonate the Guardrails or the memory slot that follow. The hash-on-yes means the file cannot predict the tag; a file that later learns it changes its hash and is dropped. Nothing is appended per turn. Children in the workspace receive the same object through `make_explore_agent_runner`, and only when `instructions.children: true`. Both knobs live on a new `InstructionsConfig` on `HarnessConfig` (`instructions: {max_ratio, children}`), **in `HARNESS_GLOBAL_ONLY_FIELDS` as its two leaves**, `instructions.max_ratio` and `instructions.children` — the `channels.remote_unattended` spelling, so a workspace block that merely restates the defaults draws no spurious warning — because `children` is a widening boolean the lower-only rule of §7.1 would not cover, and the yes covers the file, not its reach, so a workspace cannot set it. `instructions.children` is read where the runner is built (`start_cmd.py:1499`, `harness` in scope) and the record is handed into `make_explore_agent_runner` there.
- **When the hash is checked:** at every role assembly, because the role is rebuilt every turn and `CLAUDE.md` is an in-project write that `auto` never asks about. On a mismatch the section is dropped for that turn with one log line and the file is re-offered at the next open; the recorded yes never covers bytes the user did not say yes to.

## 10. Security

- `git_read` runs no repository-configured command: textconv drivers, external diff, pager, hooks, fsmonitor, signature programs, a promisor remote's lazy fetch and `-c` are out of reach by construction, the environment carries no inherited `GIT_*`, and the one path git offers no flag for — clean and process filters on a worktree-reading `diff` — is closed by the config precheck that fails closed. It never leaves the resolved workspace root: toplevel, git dir and common dir are pinned, alternates are refused, submodules are never opened, and `paths[]` can name nothing outside it — absolute, `..` after `normpath`, leading `-`, empty, control characters and `:(prefix:` are rejected before argv, magic is never parsed by git's lexical no-index test, and `--` is always emitted — so git's implicit `--no-index` (two paths, one outside) is unreachable.
- Project instructions are attacker-controlled text from a workspace file. They enter the role only after a hashed, recorded yes, fenced as project text under a harness header, and a changed file re-asks. The store is protected the way `coauthor_consent.yaml` is. The owner accepts the residual risk of a blind yes in exchange for zero friction (§13).
- A cloned repository cannot lift a budget, null a cap, widen a share or ratio, raise `channels.unattended_max_actions`, weaken `stuck_detector.*`, or push instructions into children (§6, §7.1, §7.2, §8.2) — through either workspace door, the shadowing agent file or the built-in overlay; and no configured value, from any layer, exceeds `channels.unattended_max_actions` on a remote unattended surface, because the loop applies the knob as a ceiling (§7.1).
- Reconnect re-sends an identical request; it never re-runs a tool call.
- Untrusted-origin output cannot delay escalation (§6). Trusted-origin tools whose content is attacker-influenced (`bash_exec` reading a cloned file, `agent` relaying a web summary) can delay it, bounded by the call-only ceiling and the human; the effect is liveness only, never a privilege change, and identical results still escalate as today.
- `git_read` fails closed on a repository with dubious ownership (no `safe.directory` is injected, by design), on a gitdir-file or `commondir` pointing outside the root, on `objects/info/alternates`, on a parent repository above the workspace (`GIT_CEILING_DIRECTORIES`), and on a worktree-reading `diff` in a repository that configures a clean or process filter.
- The compaction-view drop never hides a denial or a `host: dangerous` failure (§9).
- History rows gain only integers from `CompletionUsage` and a model name; the file stays 0600.
